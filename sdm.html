SDLC & Governance Command Reference Grid

Exam Quick-Reference | System Development Methodologies & Control Implications
Core Principle: The methodology shapes where and how controls are applied. No SDLC methodology is inherently insecure—security and compliance depend on adapting controls to the team's operational rhythm.
Waterfall Methodology Sequential Phase Gates & Traditional Controls
Directive / Directive Parameters / Switches Description & Control Implications Execution Example
waterfall-gate --phase=req|design|build|test|deploy Enforces sequential formal sign-offs before transitioning phases. Predictable for stable requirements, but highly inflexible; delays testing to late in the cycle. waterfall-gate --phase=test --approve
waterfall-baseline --scope=fixed --signoff=formal Establishes rigid requirement baselines. Scope changes require formal Change Control Board (CCB) review, reducing agility but streamlining compliance tracking. waterfall-baseline --scope=fixed
Agile (Scrum, Kanban, SAFe) Iterative Sprints & Audit Nuances
Directive / Directive Parameters / Switches Description & Control Implications Execution Example
agile-sprint-audit --cadence=biweekly --audit=per-sprint Audits controls on a continuous per-sprint cycle rather than end-of-project gates. Ensures rapid feedback and continuous requirement verification. agile-sprint-audit --cadence=2w
agile-backlog --item=sec-req --priority=high Embeds security controls directly into user stories and product backlogs as acceptance criteria to maintain visibility and traceability. agile-backlog --item=SEC-101
agile-retro-nuance --type=retrospective --audit-valid=false Sprint retrospectives drive internal team improvement but are NOT workpaper-equivalent. Audits require explicit baseline and control documentation. agile-retro-nuance --reject-as-wp
DevOps & DevSecOps CI/CD Pipelines & Automated Security
Directive / Directive Parameters / Switches Description & Control Implications Execution Example
devsecops-pipeline --scan=sast|dast|sca|container Integrates automated static (SAST), dynamic (DAST), dependency (SCA), and container security analysis into continuous deployment pipelines. devsecops-pipeline --scan=sast
iac-control --template=terraform|ansible --enforce=policy Manages Infrastructure as Code (IaC) via automated security policy engines. Shifts infrastructure auditing left to code reviews. iac-control --enforce=policy
pipeline-access --deploy-approval=required --mfa=true Restricts direct production access; enforces strict pipeline access controls and automated/segregated deployment gate approvals. pipeline-access --deploy-approval
RAD (Prototype-Based) & COTS (Commercial Off-The-Shelf) Rapid Prototyping & Third-Party Vendor Risk
Directive / Directive Parameters / Switches Description & Control Implications Execution Example
rad-prototype --iterative=true --risk=scope-creep Rapid Application Development uses working prototypes; risks include scope creep, skipped formal design docs, and premature production promotion. rad-prototype --iterative=true
cots-escrow --trigger=vendor-bankruptcy|default Requires source-code escrow contracts for critical third-party software to ensure business continuity if the vendor defaults or discontinues support. cots-escrow --trigger=bankruptcy
cots-sca --vendor=[name] --scan=license|vuln Runs Software Composition Analysis (SCA) on third-party commercial applications and libraries to identify embedded supply chain vulnerabilities. cots-sca --vendor=acme --scan=vuln
cots-contract --terms=sla|sec-audit|patching Enforces contractual security clauses, SLA requirements, breach notification timelines, and mandatory patching schedules on vendors. cots-contract --terms=sec-audit
